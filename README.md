# Темп — учёт рабочего времени

Небольшое веб-приложение для тестового задания Falcon Jobster: сотрудники, задачи с таймером и отчёты за выбранный период. Интерфейс на русском языке. Все демонстрационные сотрудники и задачи вымышлены.

## Быстрый запуск

Нужен **Node.js 24.15.x или более новая версия ветки 24** и npm. При использовании nvm выполните `nvm use`.

```bash
git clone https://github.com/Gringaus/falcon-time-tracker.git
cd falcon-time-tracker
npm ci
npm run build
npm start
```

Откройте **http://127.0.0.1:4317**. Сервер раздаёт готовый интерфейс и API. Отдельная установка базы данных, Docker, API-ключи и регистрация не нужны.

Режим разработки с обновлением интерфейса:

```bash
npm run dev
```

Интерфейс: http://127.0.0.1:5173, API: http://127.0.0.1:4317. `Ctrl+C` останавливает оба процесса. Если порт API занят, задайте, например, `PORT=4320 npm run dev`; прокси Vite использует тот же порт.

## Что работает

- Добавление сотрудника с именем и необязательной должностью.
- Запуск таймера с описанием задачи и остановка с сохранением записи.
- У каждого сотрудника может работать один таймер; разные сотрудники могут работать одновременно.
- Список записей, фильтр по сотруднику, готовые периоды и произвольные даты включительно.
- Итоги по каждому сотруднику, включая сотрудников с нулевым временем, и общий итог.
- Выгрузка текущего представления отчёта в CSV с кириллицей и защитой от формул.
- Адаптивная версия, управление с клавиатуры, состояния загрузки, ошибки и пустой отчёт.

Для начала работы нажмите «Добавить сотрудника», выберите его в блоке «Новая задача», введите описание и нажмите «Начать». После «Остановить» запись появится в отчёте. Смена сотрудника не останавливает его текущую задачу.

## Сохранение и правила подсчёта

SQLite хранится в `data/falcon-time.sqlite` вне сборки интерфейса. Повторный `npm start`, перезагрузка страницы и повторная сборка не очищают данные. Запущенный таймер хранится как время начала с пустым временем окончания: после перезапуска отсчёт продолжается, в том числе за время остановки сервера.

Длительность считается по серверным отметкам времени, а не по числу срабатываний `setInterval`. Интерфейс учитывает разницу часов клиента и сервера. Повторный старт защищён частичным уникальным индексом SQLite и возвращает HTTP 409; повторная остановка также возвращает 409.

В отчёт попадает только часть задачи внутри выбранного периода. Даты соответствуют часовому поясу браузера; начало и конец периода передаются с отдельными смещениями для перехода на летнее/зимнее время. Активные задачи учитываются до текущего времени. Задачи нулевой длительности сохраняются и показываются как `0 сек`. В строке и CSV указаны исходные начало и окончание задачи; длительность обрезана границами отчёта.

При первом запуске пустая база заполняется вымышленной командой и несколькими завершёнными задачами. Повторного заполнения существующей базы нет. Для отдельной пустой базы:

```bash
SEED_DEMO=false DB_PATH=./data/clean.sqlite npm start
```

Другие параметры: `PORT` (по умолчанию 4317), `HOST` (127.0.0.1), `DATA_DIR` (data). `DB_PATH` имеет приоритет над `DATA_DIR`. При переносе данных используйте резервную копию SQLite, созданную при остановленном сервере; база и её служебные файлы исключены из Git.

## Проверки

```bash
npm test                 # HTTP API, бизнес-правила и сохранение в SQLite
npm run build            # строгая проверка TypeScript и production-сборка
```

Браузерный сценарий использует Playwright и отдельную временную базу, которую удаляет после завершения:

```bash
npx playwright install chromium
npm run test:e2e
```

Если Google Chrome уже установлен, можно использовать его:

```bash
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

Тест самостоятельно собирает интерфейс и запускает временный сервер на порту 4318. Данные обычного приложения он не меняет. При необходимости `E2E_BASE_URL` позволяет проверить заранее запущенный тестовый экземпляр; в таком случае тест добавит в него вымышленные записи.

Основные сценарии: создание сотрудника → запуск → отказ повторного запуска → перезагрузка с сохранённым таймером → остановка → отчёт и CSV. Отдельно проверяются пустой отчёт, обратный порядок дат, границы периода и часового пояса, переход DST, одновременные запросы, мгновенная остановка, сохранение завершённого и активного таймера после повторного открытия файла БД. Браузерный тест проверяет отсутствие ошибок JavaScript и горизонтального переполнения страницы на экране 390 × 844.

GitHub Actions запускает эти же проверки при push и pull request.

## Код и выбор стека

```text
src/components/  Таймер, форма сотрудника, список команды, отчёт
src/App.tsx       Компоновка, загрузка состояния и навигация
src/api.ts        Общая обработка HTTP-ответов
server/app.mjs    Маршруты HTTP и раздача интерфейса
server/store.mjs  SQLite, валидация, таймеры и расчёт отчёта
tests/            Интеграционные тесты node:test
e2e/              Браузерный сценарий Playwright
```

React + TypeScript + Vite для интерфейса; стандартные `node:http`, `node:sqlite` и `node:test` для сервера, базы и тестов. Такой объём задания позволяет обойтись без Express, ORM и отдельного сервера БД. API и интерфейс работают с одного origin. Точное дерево зависимостей закреплено в `package-lock.json`.

Документация, использованная при реализации: [Node.js SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html), [Vite proxy](https://vite.dev/config/server-options.html#server-proxy), [GitHub checkout](https://github.com/actions/checkout), [GitHub setup-node](https://github.com/actions/setup-node).

## Применение ИИ

Код, декомпозиция, тесты и независимая проверка подготовлены с помощью **Codex, агента на базе GPT‑6**. Подзадачи сервера, отчёта и проверки кода выполнялись параллельными агентами. Конкретный суффикс/снимок модели средой не сообщён, поэтому здесь он не придуман. **Встроенный Image Gen** использован для визуального концепта; ID модели инструмент не раскрывает. В самом приложении запросов к ИИ нет.

Примеры фактически использованных запросов к агентам, сокращённые без изменения смысла:

1. «Implement backend and meaningful node:test tests for time tracking assignment… Use native node:http + node:sqlite (no backend deps)… SQLite file… start task timer description per employee with unique running per employee constraint… report… clipped durations across selected period boundaries + live timers».
2. «Implement src/components/Report.tsx ONLY… date filters Today/rolling last 7 days/This month and custom from/to, employee dropdown, two tabs Записи/По сотрудникам… CSV download… loading/error/empty state with retry… AbortController avoid stale».
3. «Read-only independent review… practical correctness and edge cases, list only material bugs with file/line and fix recommendation… Focus… race same timer, reports boundaries, empty state, UI usability/accessibility».

Полный запрос к Image Gen сохранён в [docs/design-prompt.txt](docs/design-prompt.txt), исходный концепт — [docs/design-concept.png](docs/design-concept.png). Это визуальный ориентир; интерфейс написан настоящими компонентами, таблицами и формами.

### Что нашли и исправили при проверке

- **Исчезновение мгновенно завершённой задачи.** Отбор `durationMs > 0` исключал сохранённую запись нулевой длительности. Исправлен отбор пересечения периода, добавлен регрессионный тест.
- **Часовой пояс при переходе DST.** Одно смещение для обеих границ могло давать ошибку в час. Передаются и проверяются отдельные `tzStart`/`tzEnd`; тест охватывает сутки длительностью 23 часа.
- **Фокус в диалоге.** React-фокус до вызова `showModal()` сменялся фокусом на кнопке закрытия. Теперь поле имени получает фокус после открытия; браузерный тест проверяет это.
- **Разные ограничения формы и API.** Форма допускала 100 символов, сервер — 80. Ограничения синхронизированы: имя 2–80, должность до 80, описание задачи до 500 символов.
- **Закрытие формы при клике по внутреннему отступу.** Проверки только `event.target` было недостаточно. Закрытие по фону учитывает координаты относительно границ диалога.
- **Узкая колонка задачи на телефоне.** Длинное имя сотрудника сжимало соседний столбец до нескольких букв в строке. Задана минимальная ширина текста задачи; таблица прокручивается внутри своего контейнера. Браузерный тест проверяет читаемую высоту строки и отсутствие переполнения страницы.

## Границы решения

Это небольшое приложение без авторизации и сложных ролей по условиям задания. Оно рассчитано на локальную демонстрацию и вымышленные данные. Отдельного облачного демо нет. Все записи загружаются целиком; для большой истории следующим шагом будут пагинация и агрегация на стороне БД. Изменение и удаление записей, округление рабочего времени и производственный календарь в объём задания не включены.
